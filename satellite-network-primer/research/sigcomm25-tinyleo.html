Small-scale LEO Satellite Networking for Global-scale Demands (TinyLEO)以小規模 LEO 衛星網路滿足全球規模需求（TinyLEO）

ACM SIGCOMM 2025Yuanjie Li, Yimei Chen, Jiabo Yang, Jinyao Zhang, Bowen Sun, Lixin Liu, Hewu Li, Jianping Wu, Zeqi Lai, Qian Wu, Jun Liu (Tsinghua University. Zhongguancun Laboratory) · paper論文 peer-reviewed

TinyLEO designs sparse constellations around geographic demand. Examine Earth-repeat orbits, model-predictive link control and geographic forwarding, with explicit limits on the Starlink baseline.TinyLEO 依地理需求設計稀疏星座。導讀說明地球重複軌道、模型預測鏈路控制與地理轉送，並界定 Starlink 比較基準的範圍。

TinyLEO matches orbit coverage to concentrated geographic demand. Matching pursuit selects Earth-repeat orbits, an orbital model-predictive controller favors long-lived ISLs through stable matching, and SRv6 forwards using geographic segment anycast. Synthesis results use fewer satellites than the dated Starlink fleet under the estimated demand [39, §6.1]. StarryNet emulation supplies control, repair and routing results [39, §6.2–6.3]. The model adopts company-stated link budgets and a standard three-ISL grid because Starlink's actual topology remains confidential. Tables distinguish synthesis assumptions from emulated network measurements.

TinyLEO 讓軌道覆蓋配合集中的地理需求。匹配追蹤選出地球重複軌道，軌道模型預測控制器以穩定配對偏好長壽鏈路，SRv6 則使用地理區段任播。在估計需求下，合成星座的衛星數低於指定日期的 Starlink 機隊[39, §6.1]，控制、修復及路由結果則來自 StarryNet 模擬平台[39, §6.2–6.3]。模型採公司聲明的鏈路預算，並因 Starlink 實際拓樸保密而使用標準三 ISL 網格。表格區分合成假設與模擬網路量測。

1. Where this paper sits1. 這篇論文的位置

TinyLEO illustrates the move from fixed link patterns to time-varying control in Chapter 5. The Tsinghua team's earlier work identified maneuver-induced link failures and unstable satellite-identity routing. This system combines orbit synthesis, geometry-aware topology control and forwarding keyed to Earth-fixed cells. Its stated per-satellite budget and explicit proxy-topology qualification also support Chapter 4's parameter sheet.

TinyLEO 呈現第 5 章從固定鏈路樣式走向時變控制的研究方向。清華團隊先前的工作指出軌道機動會中斷鏈路，衛星身分路由也會隨變動受到擾動。系統將軌道合成、依幾何調整的拓樸控制，以及地球固定格元轉送整合起來。明確的每衛星預算及代理拓樸限定，也提供第 4 章參數表的依據。

2. The problem, measured2. 問題，用量測說話

Uniform shells distribute coverage across oceans, deserts and cities, while the cited demand data concentrates users on a small land area [39, §1, §2.2]. TinyLEO tests a demand-matched design through synthesis. It assigns required capacity to Earth-fixed cells and checks spare access and ISL capacity at each time step. The baseline uses real Starlink positions from a dated fleet snapshot [39, §6.1]. Demand remains an acknowledged estimate, so satellite counts depend on those inputs.

均勻殼層將覆蓋分配至海洋、沙漠與城市，引用的需求資料則將使用者集中於少量陸地[39, §1, §2.2]。TinyLEO 透過合成測試依需求配置的設計，為地球固定格元指定所需容量，並在每個時間步檢查接取與 ISL 的剩餘容量。基準使用指定日期的實際 Starlink 衛星位置[39, §6.1]。需求仍是作者承認的估計，因此衛星數量取決於這些輸入。

3. The design3. 設計

The synthesis layer selects Earth-repeat orbits whose ground tracks revisit the same demand cells. Matching pursuit greedily adds the orbit that reduces unmet demand most, while exact Gurobi runs remain unfinished at the comparison cutoff [39, §6.1]. The orbital model-predictive controller translates geographic intent into link schedules using predicted geometry and Gale–Shapley matching that favors long-lived partners [39, §4.2]. The data plane encodes cells as SRv6 segments, allowing any satellite covering a cell to forward toward the next cell [39, §4.3]. Covering satellites handle failures locally while the controller recompiles in the background. The tables separate local reroute time from controller repair and signaling.

合成層選擇地面軌跡會重訪相同需求格元的地球重複軌道。匹配追蹤每次加入最能減少需求缺口的軌道，精確 Gurobi 則在比較截止時仍持續求解[39, §6.1]。軌道模型預測控制器根據預測幾何，以偏好長壽對象的 Gale–Shapley 配對，將地理意圖轉成鏈路時程[39, §4.2]。資料平面將格元編碼為 SRv6 區段，讓當前覆蓋該格的任何衛星朝下一格轉送[39, §4.3]。覆蓋衛星先就地處理故障，控制器同時在背景重新編譯，表格區分局部重繞、控制器修復與訊令時間。

4. Evaluation setup4. 實驗設定

The satellite-count study uses synthesis simulation with demand, orbit and position data from Space-Track, ITU and Cloudflare Radar. Gurobi supplies a time-limited exact baseline. Control and forwarding results come from a hardware-in-the-loop StarryNet variant using Linux containers, with configured link capacity and delay. Company specifications supply the access and ISL budgets.

Cell size bounds hop delay, while node delay, laser acquisition cost and user-link reconfiguration require additional models. Baselines include real Starlink positions, MegaReduce, Gurobi, TS-SDN with route aggregation enabled or disabled, and grid- or MPC-controlled Starlink variants. The stretch result uses the MPC-controlled variant.

衛星數研究採合成模擬，需求、軌道及位置資料來自 Space-Track、ITU 與 Cloudflare Radar，Gurobi 則提供設有截止時間的精確基準。控制與轉送結果來自硬體在環的 StarryNet 變體，以 Linux 容器執行，鏈路容量及延遲均由設定提供。接取與 ISL 預算取自公司規格，每跳延遲以格元大小為界。節點延遲、雷射擷取成本與使用者鏈路重組仍需額外模型。基準包含實際 Starlink 位置、MegaReduce、Gurobi、啟用或停用路由聚合的 TS-SDN，以及網格控制或 MPC 控制的 Starlink 變體，延展比採後者作比較。

6. Limits and open questions6. 限制與待研究的問題

  • Estimated demand sets the synthesis scope. Customer maps and Cloudflare Radar supply capacity and geographic distribution. Satellite counts scale with those inputs, as the paper acknowledges in its limitations.估計需求界定了合成範圍。容量與地理分布取自客戶地圖及 Cloudflare Radar，衛星數隨這些輸入縮放，論文也在限制中說明此條件。
  • Company specifications set the link budget. TinyLEO uses the stated peak rate, while the fact base distinguishes peak and sustained figures relayed by journalists. Range-dependent performance and an optical link budget require separate analysis.公司規格設定了鏈路預算。TinyLEO 採用聲明的峰值速率，事實庫則區分記者轉述的峰值與持續數值。距離相關效能及光學鏈路預算仍需另外分析。
  • Acquisition time requires an explicit budget. Lifetime-aware matching reduces repointing frequency, but each new link still requires setup. Daily acquisitions per satellite would help determine whether the compiled topologies remain feasible under real terminal timing.擷取時間需要明確預算。考量壽命的配對可減少重新指向頻率，每條新鏈路仍需建立。量化每顆衛星每日擷取次數，有助於判定編譯拓樸在真實終端時間下的可行性。
  • The delay scope covers the ISL mesh. Cell size bounds per-hop delay, while node processing and user-link reconfiguration need separate models. Read failover and stretch results within that scope.延遲範圍涵蓋 ISL 網格，每跳延遲以格元大小為界，節點處理與使用者鏈路重組則需要另外建模。故障切換與延展比結果應依此範圍解讀。
  • Earth-repeat orbits constrain coverage. The sparse design depends on repeated ground tracks and the discrete altitude family in Table 1. Drag, maneuvers and observed daily shell changes require further assessment of repeat-track stability.地球重複軌道限制了覆蓋設計。稀疏配置依賴重複地面軌跡及 Table 1 的離散高度集合，阻力、機動及實測每日殼層變化對重複軌跡穩定性的影響，仍需進一步評估。
  • Centralized control makes repair depend mainly on signaling distance. The measured repair budget is dominated by the controller round trip. The paper identifies centralization as a limitation.集中控制使修復主要取決於訊令距離，量得的修復預算由控制器往返時間主導，論文也將集中化列為限制。
  • The baselines answer separate questions. Real Starlink positions support satellite-count comparisons, while the authors' MPC supplies the routing comparison. The timed-out Gurobi run leaves an open optimality gap for synthesis.各項基準回答的問題各有範圍。實際 Starlink 位置支持衛星數比較，作者的 MPC 則提供路由比較。Gurobi 在截止時仍持續求解，使合成結果與最佳解的差距仍待確認。
