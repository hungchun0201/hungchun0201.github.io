The companion primer explains three ways to split a large model across workers. Their traffic patterns determine how well they fit an orbital network. Tensor parallelism splits each layer’s weight matrices across a small accelerator group, which exchanges partial activations several times per layer. It requires the highest bandwidth and lowest latency, so Meta’s Llama 3 report keeps it within a host at TP = 8 [77, §3.3.2] preprint. Pipeline parallelism assigns consecutive layers to stages.

Adjacent stages exchange forward activations and backward gradients once per micro-batch, moving few bytes on each step’s critical path. Data parallelism replicates the model and assigns each replica a separate batch slice. It combines gradients through an all-reduce, which gives every worker the element-wise sum of all workers’ vectors so every replica applies the same update. The volume of that collective is proportional to model size with batch size independent of that volume. This explains why it is the term that a slow inter-satellite fabric will feel first.

姊妹教材花了三章說明大型模型如何切分到多個工作者上，而軌道問題只需要知道每一種切法會產生什麼流量。張量平行把每一層的權重矩陣切到一小群加速器上，每層要交換部分激活值好幾次，因此它對頻寬與延遲的要求是三者之中最高的，通常被限制在一台主機之內，Meta 的 Llama 3 報告把它設為 TP = 8[77, §3.3.2]preprint。流水線平行把連續的層分配到各個階段，相鄰階段之間每個微批次傳一次前向激活值與反向梯度，位元組數較少，卻落在每一步的關鍵路徑上。資料平行則把整個模型複製多份，各副本處理各自的批次切片，然後必須合併梯度讓每個副本套用相同的更新，這件事靠的就是全歸約（all-reduce），也就是讓每個工作者最後都拿到所有工作者向量逐元素總和的集體通訊。這個集體通訊的資料量與模型大小成正比，批次大小則維持獨立，所以它會是慢速星間網路最先感受到的那一項。

The all-reduce cost follows directly from the bytes that a ring must move. A ring all-reduce has N workers, each holding M bytes, and starts with reduce-scatter. Each worker sends one N-th of its vector right and adds the vector arriving from the left. After N − 1 repetitions, each worker holds the complete sum of one shard. All-gather then circulates the finished shards for another N − 1 steps.

Each step sends M/N bytes from every worker. Both phases therefore move 2(N − 1)M/N bytes per worker, approaching 2M from below as N grows. A cut halving the group carries M/2 bytes per direction during reduce-scatter. All-gather returns another M/2 bytes per direction as finished shards. The total is M bytes per direction.

Divide per-worker bytes by injection rate to obtain the all-reduce injection bound. Divide cut bytes by bisection bandwidth to obtain the cut bound. Injection governs when bisection exceeds half of one worker’s injection rate, as the table shows. Ring all-reduce therefore stresses worker links, while all-to-all expert dispatch stresses the cut. Section 10.4 uses this distinction.

全歸約的成本可以從「環必須搬多少資料」直接算出來，以下直接列出推導。設 N 個工作者各持有 M 位元組的向量，環狀全歸約先做歸約散佈（reduce-scatter）：每個工作者把自己向量的 N 分之一送給右鄰，並把左鄰送來的加進來，重複 N − 1 次之後每個工作者手上都有某一個分片的完整總和。接著做全收集（all-gather），讓完成的分片再繞行 N − 1 步。每一步從每個工作者送出 M/N 位元組，所以兩階段合計每個工作者送出 2(N − 1)M/N 位元組，隨 N 增大趨近於 2M ，上限為 2M。同一套計數也決定了任何把群組對半切開的切面上會流過多少資料：歸約散佈必須把另一半的部分和送過來（每個方向 M/2 位元組），全收集又必須把完成的分片送回去（每個方向再 M/2），因此切面每個方向總共承載 M 位元組。

把每工作者位元組除以工作者的注入速率就得到全歸約時間的注入下界，把切面位元組除以對切頻寬就得到切面下界，而下方的算式表顯示：只要拓樸的對切頻寬超過單一工作者注入速率的一半，起作用的就是注入下界。第 10.4 節會倚賴的實際結論是：環狀全歸約吃緊的是工作者自己擁有的鏈路，切面上的流量則較少。反之，像混合專家模型裡的專家分派這類全對全（all-to-all）模式吃緊的才是切面。

The three regimes define the scope of van Berkel’s verdict. He places two-to-three-year orbital frontier training outside credible scenarios and judges a ten-year horizon optimistic [101, §V] preprint. The question for Chapter 11 is a formation fabric meeting Figure 10.3’s rate requirements. It must recover torus capacity, place tensor-parallel boundaries across apertures and preserve its compute advantage after corruption recovery and redundancy costs.

對照這三種體制來讀，van Berkel 的結論比它的標題所暗示的範圍更窄，也因此更站得住腳。他的結論是，兩到三年內的太空前沿訓練超出其可信情境，十年的時程則仍偏樂觀[101, §V]preprint。而理由與本章各節一一對應：唯一有足夠鏈路速率的體制，若接成環面，對切頻寬會比地面 Clos 少兩到三個數量級（第 10.4 節），若接成 Clos，則要用運算衛星來付代價，而且還繼承了高於地面參考的失效假設（第 10.5 節）。至於真的飛上去過的體制，僅使用本地互連。因此本章交給第 11 章的開放問題，聚焦於編隊網路如何補回環面的容量損失、正確安排跨孔徑的張量平行邊界，以及在計入冗餘成本後保有運算優勢，並撐過無聲損毀。
